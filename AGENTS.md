# Architecture rules
- Public /book and /auth responses use utility-route-seo in postbuild-seo and SEOHead for matching initial/rendered noindex metadata; never prerender authenticated portals, and allow utility crawling so noindex is readable.
- Outside-hours creation requires explicit internal-form opt-in and a server-verified admin role; public/client scheduling never opts in, so owner exceptions cannot widen customer hours.
- Store the featured Google review selection as one atomic, admin-only editable collection in public.featured_google_reviews; public readers receive only complete selections, preventing partial updates across pages.
- Keep review validation and access in one repository, and render public reviews through GoogleReviews on every page so content and behavior cannot diverge.
- Keep homepage FAQ answers force-mounted but hidden when collapsed, and wait for data-crawl-pending to clear before prerender capture so initial HTML contains real content without changing accordion behavior or adding review schema.
- Keep account email dispatch in the scaffolded managed SDK handler; preserve independent Resend feature senders so the email update does not change their provider or content.
- Record booking changes via the bookings_audit database trigger into public.booking_audit_log, never from app code, so every change path (app, functions, admin) is captured.
- Keep card data in Stripe; use the authenticated card-wallet function and durable per-booking authorization/reservation guards for balance charges, refusing ambiguous ledgers and uncertain retries to avoid unauthorized or duplicate payments.
- Settle portal charges atomically with a service-only database function and serialize payment/deposit writes on the booking lock so ledger, receipt and booking payment state cannot diverge.
- Publish customer service notes separately from internal notes, and keep documents protected by booking ownership so staff-only content never appears in the customer portal.
- Render customer appointment photos through AppointmentPhotos using short-lived private URLs, with distinct before/after groups and retryable loading, so failures never appear as missing records.
- Store reminder preferences and STOP suppression durably, and claim each appointment/channel/time reminder before dispatch through existing Resend and Twilio providers to honor consent and prevent duplicate sends.
- Authenticate reminder cron callbacks with a private service-only scheduler credential; never embed tokens in cron definitions or expose the credential through customer access.
- Public prices come only from src/lib/pricing.ts (active service_packages, membership_plans, and the booking flow's ceramic tiers) so pages and booking cannot contradict each other.
- Booking uses active authoritative package/add-on rows with shared booking-pricing cent arithmetic and vehicle resolution; checkout charges persisted bookings.total_price without re-adding add-ons or included fees, so the quoted and collected amounts agree.
- Each public page emits exactly one LocalBusiness JSON-LD (from localBusinessSchema, referenced elsewhere by @id); main.tsx clears prerendered JSON-LD before Helmet re-adds it, so schemas never duplicate after hydration.
- Legacy /services/* and /terms URLs are served as noindex canonical+refresh stubs by postbuild-seo (static hosting can't send 301s) plus client Navigate routes; internal links always use the keyword landing URLs.
